Status: active research note  
Branch: `research/p2-price-mechanics`  
Model A / Model B parameters: **unchanged**

## Executive finding

The "今天几星" history chart must be treated as a **retrospective, versioned backcast dataset**, not automatically as contemporaneous published truth.

The strongest evidence is the feature timeline preserved in archived 银行螺丝钉 WeChat articles:

1. **2023-05-24 — Mini Program launch**
   - "今天几星" was introduced as a new Mini Program.
   - At launch, star broadcasts were described at fixed trading-day times:
     - 09:30
     - 12:00
     - 14:30
     - 16:00
   - The article says additional useful functions would be developed and launched later.
   - Source: [白天怎么看星级：「今天几星」小程序来啦～](https://mp.weixin.qq.com/s?__biz=MzAwNzQ5ODk3Nw==&mid=2651069064&idx=2&sn=e6ad16465605380eca284987cfc18102&chksm=816b512512651dac4a2df208d968528341c76582e0d345a45637e75d7ac6797d22297cab6dcc#rd)

2. **2023-07-17 — Historical-star query explicitly launched as a new feature**
   - The article says the Mini Program had **"上线了一个新功能：历史星级查询"**.
   - UI path: homepage top -> "查看历史星级" -> historical chart.
   - Pressing the chart could select a date and show the historical star together with the 中证全指 level.
   - At that time the UI exposed **2014 to then-current data**.
   - Crucially, the article also says **pre-2014 data already existed**, but was waiting for backend optimization before being exposed.
   - Source: [7月17日指数估值数据（历史星级可以随时查看啦～）](https://mp.weixin.qq.com/s?__biz=MzAwNzQ5ODk3Nw==&mid=2651070311&idx=1&sn=5198dab737f7e60fe2dddc5e6eff4b4c&chksm=81edb3102c3656d9b74ea6b5b35a604a8c7247f81de68d3c35f6f997a65afba1e9e9a8aeeffa#rd)

3. **2024-07-20 — cadence upgraded to minute-level**
   - The article says the Mini Program could show the latest star **updated every minute**.
   - Historical stars remained a separate feature alongside valuation tables and the bull/bear dashboard.
   - Source: [每日钉一下（「今天几星」支持每分钟实时更新星级）](https://mp.weixin.qq.com/s?__biz=MzAwNzQ5ODk3Nw==&mid=2651080213&idx=3&sn=58dbfed0340bf7ee5a3f2d3cd8825db1&chksm=814b69612399848bb1f2f366a2bc3eec3216a266d311dd4f89851a42356fb0d0b49a68e0405a#rd)

4. **2026 — public descriptions say the chart reaches back to 2012**
   - Existing project evidence already records 2026 descriptions allowing inspection of trading days since 2012.
   - Therefore the visible history coverage was expanded after the 2023 history feature launched.

## Mini Program identity recovered

Archived publisher HTML exposes the Mini Program metadata directly:

```text
nickname = 今天几星
appid    = wx132d40a0c36674a6
path     = pages/discovery/index
```

The same AppID and entry path were found in multiple archived articles spanning:

- 2023-05-24 launch
- 2023-07-17 historical-star feature
- 2024-04-24 valuation-table feature
- 2024-07-20 minute-update description
- 2024-08-27 usage guide
- 2024-09-03 valuation content

No separate history route was exposed in the publisher HTML. This is consistent with the history view being an in-page tab/component whose data are loaded at runtime.

## Implication for target governance

Do not merge current-app historical values into the contemporaneous target table without provenance.

Maintain at least these dimensions:

```text
query_date
star_date
source_type
capture_date
app_version_if_known
value
granularity
evidence_url_or_artifact
```

Recommended source types:

```text
contemporaneous_published_star
current_app_backcast_star
historical_app_capture_<capture_date>
retrospective_article_statement
```

The current app history is useful, but its primary role is now:

1. recover a dense retrospective series;
2. compare that series against contemporaneous published stars;
3. identify whether historical values were recomputed under a later methodology;
4. determine whether the apparent cross-cycle anchor drift is a real production mechanism, a methodology reset, or a backcast-version artifact.

## Highest-value next acquisition

Capture the network traffic generated by a normal user-controlled Mini Program session while:

1. opening `pages/discovery/index`;
2. entering "查看历史星级";
3. loading the chart;
4. selecting dates in different eras (e.g. 2014, 2018, 2021, 2023);
5. changing the visible date range if the UI supports it.

Export the capture as HAR (or equivalent request/response JSON) and run:

```bash
python research/extract_today_star_har.py capture.har --json-out today_star_candidates.json
```

The analyzer deliberately redacts obvious cookies/tokens and ranks endpoints containing:

- historical date series;
- star/score/rating fields;
- `000985` / 中证全指 references;
- history/chart/trend URL patterns.

## Decision rule after API recovery

If a dense app-backcast series is recovered, **do not refit Model A or Model B first**.

Run three comparisons:

1. **Version consistency**
   - current app backcast vs contemporaneous published targets on overlapping dates.

2. **Cross-cycle model discrimination**
   - static-round vs fixed-slope moving-anchor on 2014–2021 backcast;
   - then repeat on contemporaneous-only anchors where available.

3. **Reset detection**
   - test for step changes in implied anchor:
     `A_t = S_t - beta * ln(P_t)`,
     keeping `beta = -4.127707783337646` fixed for the diagnostic.

Any newly inferred reset/anchor rule remains exploratory until independently validated. Frozen Model A and Model B stay unchanged.
